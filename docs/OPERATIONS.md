# Operations

How the automated parts run, and what to do when they don't. Design decisions live in [VISION.md](VISION.md); this is the runbook.

Everything here assumes **one machine** — the Mac you work on. That machine runs the scheduled sync, holds the Blackboard session, and has the logged-in Claude CLI. If you later want the sync on a separate always-on machine, see [ADAPTING.md](ADAPTING.md); nothing in the repo changes.

## The scheduled job

- **Trigger:** launchd agent `com.course-brain.lecture-sync`, plist at `~/Library/LaunchAgents/`. Run times = each class's end time + 30 min, plus 07:05 every weekday (so schedule changes propagate even on days with no class). Generated by `scripts/gen-schedule.py` from the `schedule:` line in every `class.md`. Classes past their `ends` date drop out automatically. Install or refresh it any time with `python3 scripts/gen-schedule.py`; preview with `--dry-run`.
- **Payload:** `scripts/lecture-sync-job.sh` — `git pull` (if a remote exists) → headless `claude -p "/lecture-sync"` (40 min timeout) → `scripts/blackboard-job.sh`. Everything from the scan onward lives in that second script, shared with the poll job below; the lecture job runs it with the mirror forced, since the class that just ended is the one with new material. The shared tail is: `scripts/blackboard-scan.py` (diff the gradebook, file new assignments, fix due dates that moved, flag anything ambiguous to `inbox/blackboard-review.md`) → `scripts/blackboard-mirror.py` (refresh each class's `harvey/` mirror in its workdir) → copy this repo's CLAUDE.md into every workdir and semester root as `_course-brain-rules.md` → `scripts/todoist-sync.py` (refresh task descriptions and due dates from the files, pull your task comments into `## Notes`, flip files whose task was checked off to `submitted`) → commit + push if anything changed → regenerate the schedule → optional ntfy ping. If the lecture run failed, only the scan/Todoist outputs and any review flags are committed that run — lecture files the failed run left behind stay uncommitted until the next successful run sweeps them up as-is.
- **The ping is decision-only:** it fires only for review-file entries that haven't been pinged before (state: `~/.course-brain/pinged-flags`, one flag heading per line — delete a line to re-ping it), and the body is the new flags' headings, so the notification itself states each decision. Routine runs (lectures filed, descriptions refreshed, auto-applied due changes) are silent — they're in the log, not on your phone.
- **Logs:** `~/Library/Logs/course-brain/lecture-sync.log`. One `=== run <timestamp> ===` block per run.
- **Lock:** `/tmp/course-brain-sync.lock` (a directory holding the pid). Stale locks from crashed runs are detected and taken over. Before pulling, the job also waits up to 5 min for `/tmp/course-brain-poll.lock` to clear so a poll run mid-flight can finish; if it doesn't, the job logs that and proceeds.
- **Scan state:** `classes/<class>/.bb-manifest.json` — the last gradebook and content tree seen, committed to the repo. It's what keeps a rerun with no upstream changes from re-filing or re-flagging anything. Delete it to make the next run treat the class as brand new.
- **Mirror state:** `classes/<class>/.bb-mirror.json`, also committed. Shape:

  ```json
  {
    "files": {
      "<contentid>::<name>": {
        "bytes": 182344,
        "remote_bytes": 182344,
        "path": "Module 1/lecture-01.pdf",
        "url": "/bbcswebdav/...",
        "mirrored_at": "2026-08-27"
      }
    },
    "dead": {}
  }
  ```

  `files` is every file the mirror put under `harvey/` — `path` is relative to `harvey/`, `bytes` is what actually landed on disk, `remote_bytes` is the size Blackboard reported (they don't always agree, so both are kept). A `page::<itemid>` key with `"page": true` is an Ultra page body the mirror rendered to markdown rather than downloaded; it carries a `hash` of the rendered text instead of a remote size, and is pruned like any other entry. `dead` holds links Blackboard still lists but that 4xx on download, so a rerun doesn't retry them forever. Two more keys appear as the mirror learns: `items` (per-content-id `modifiedDate` + body hash, for change detection) and `specs`/`tests` (which assignment files the mirror owns the spec text of). Delete the whole file to re-mirror a class from scratch.

## The poll job (optional)

The lecture job only fires a few times a week, so a gradebook column posted during an evening class sits unseen until the next morning. The poll gives Blackboard its own lightweight run in between.

- **Trigger:** launchd agent `com.course-brain.blackboard-poll`, plist at `~/Library/LaunchAgents/`. `StartInterval` 1800, so every 30 minutes from whenever launchd loaded it. Installed by `scripts/gen-schedule.py` alongside the lecture agent; `python3 scripts/gen-schedule.py --no-poll` skips it and removes it if it's already installed.
- **Hours:** the plist fires all day; the script exits immediately (and silently, nothing in the log) outside 07:00–22:59 local. Nothing gets posted at 4am, and a relogin at 4am would burn a browser launch nobody sees.
- **Payload:** `scripts/blackboard-poll-job.sh` — `git pull` → `scripts/blackboard-job.sh`, the same tail the lecture job runs. Same decision-only ping and same `~/.course-brain/pinged-flags` state, so a flag pings once no matter which job finds it.
- **Mirror gating:** the scan is 2–3 requests per class and catches new columns and items, so it runs every time. The mirror is 50–90 requests even when nothing changed, so the poll only runs it when the scan left a `classes/*/.bb-manifest.json` dirty, or when `~/.course-brain/last-mirror` is missing or over 2 hours old. That stamp is touched after each successful mirror. The lecture job passes `CB_FORCE_MIRROR=1` and always mirrors.
- **Logs:** `~/Library/Logs/course-brain/blackboard-poll.log`. One `=== run <timestamp> ===` block per run, closed by `--- done <timestamp> ---`, so a run that never finished is obvious.
- **Lock:** `/tmp/course-brain-poll.lock` (a directory holding the pid), same stale-takeover as the lecture job. It also reads `/tmp/course-brain-sync.lock`: if a lecture run is live, the poll logs `deferring to lecture-sync` and exits rather than waiting, since that job does everything this one does and more.
- **Failure ping:** consecutive `blackboard-scan.py` failures are counted in `~/.course-brain/scan-failures`; a success deletes the file. At three in a row the job pings your phone with `course-brain: blackboard scan failing`, then at most once a day after that (`~/.course-brain/scan-failure-pinged` is the timestamp). This is the one non-decision ping in the system, on purpose: a broken Blackboard login is otherwise silent until someone reads the log.

Test a run without the write-back steps. It still logs into Blackboard, runs the scan (which can write assignment files, manifests and review flags), refreshes the mirror in the workdir, and moves the `last-mirror` stamp:

```bash
CB_DRY=1 zsh scripts/blackboard-poll-job.sh; tail -20 ~/Library/Logs/course-brain/blackboard-poll.log
```

`CB_DRY=1` runs the scan, the gated mirror and the rulebook copy, then stops and prints what it would have staged. No Todoist, no commit, no push, no schedule regeneration, no pings. It is not read-only.

### Phone approval flow (optional)

The scan never guesses, and neither does the lecture flow: an ambiguous Blackboard change, or a deadline spoken in class that differs from a filed assignment's `due:`, goes to `inbox/blackboard-review.md` and shows up in the ping. To handle it from anywhere: tap the ping (it opens claude.ai/code), open this repo, and say "process the blackboard review file". The agent walks the entries with you, applies or drops each one, and commits. Todoist catches up on the next run.

To enable pings: pick a hard-to-guess [ntfy.sh](https://ntfy.sh) topic (e.g. `course-brain-` plus a random suffix — knowing the name is the only thing gating reads and publishes, so make it unguessable and keep it out of the repo), subscribe to it in the ntfy phone app, and write it to `~/.course-brain/ntfy-topic` — one line, the topic name or a full url. No file, no pings; everything else still runs.

## Blackboard session

`scripts/bb` wraps `scripts/blackboard.py` — a Playwright SSO login plus a small API client for Blackboard Ultra, default base `harvey.utulsa.edu` (override with `CB_BB_BASE`).

- **State:** `~/.course-brain/bb-state.json` (cookies, `chmod 600`). Per-machine, never in the repo. Delete it to force a fresh login.
- **Credentials:** a 1Password item holding your school login — username, password, and one-time password — read via `op`. Item name defaults to `Utulsa`; override with `CB_OP_ITEM` (and `CB_OP_VAULT` if the item isn't in your default vault). Interactive use works through the 1Password desktop-app integration; unattended runs need `OP_SERVICE_ACCOUNT_TOKEN` in the environment (create a [service account](https://developer.1password.com/docs/service-accounts/) scoped to just that vault — a service account must name an explicit vault, so set `CB_OP_VAULT` too). launchd jobs don't inherit your shell environment: put such variables in `~/.course-brain/env` (`chmod 600`, plain `export KEY=value` lines) — the job script sources it at startup. Using something other than 1Password? See [ADAPTING.md](ADAPTING.md).

Commands:

```bash
scripts/bb check                      # "ok: <user>" (0) or "no session" / "expired" (2)
scripts/bb login                      # full SSO login, saves state. --headed to watch it
scripts/bb get /learn/api/v1/users/me # any api path, re-logs in once if the session is dead
scripts/bb get <path> --html          # a classic /webapps/ page (discussion boards etc.)
scripts/bb head <path>                # size/etag/last-modified without the body
scripts/bb download <path> <dest>     # raw bytes for one file, authenticated
scripts/bb courses                    # memberships, one line per course
```

Course files are mirrored, not fetched one at a time. `scripts/blackboard-mirror.py [class-code] [--dry-run]` walks a class's content tree, downloads every file into the class's workdir under `harvey/` (same folder structure as Blackboard), and fills assignment spec text into `classes/<class>/assignments/*.md` where the `Full spec on Harvey (not yet mirrored).` placeholder sits. It's idempotent — state lives in `classes/<class>/.bb-mirror.json`, so a rerun only picks up what's new.

`harvey/` is owned by the script: it's pruned to match Blackboard, so a file taken down online is deleted locally, and the folder can be deleted and regenerated at will. Nothing should be hand-placed in it. The workdir's other folders — `materials/`, `homework/`, `exams/`, `projects/`, `grading/` — are yours, and the sync never touches them.

One-time setup on a machine — a playwright venv plus the 1Password CLI (`brew install 1password-cli`):

```bash
uv venv ~/.course-brain/venv --python 3.12
uv pip install --python ~/.course-brain/venv/bin/python3 playwright
```

No browser download needed — the script drives the installed Google Chrome (`channel=chrome`). If there's no venv, `scripts/bb` falls back to `uv run --with playwright`, which is slower but works. ([uv](https://docs.astral.sh/uv/) is the only tool assumed.)

## Common tasks

Check recent runs:

```bash
tail -40 ~/Library/Logs/course-brain/lecture-sync.log
```

Force a run now:

```bash
zsh scripts/lecture-sync-job.sh; tail -15 ~/Library/Logs/course-brain/lecture-sync.log
```

Force a Blackboard poll now (this one commits and pushes; add `CB_DRY=1` to skip Todoist, commit, push and pings, though it still scans and mirrors):

```bash
zsh scripts/blackboard-poll-job.sh; tail -15 ~/Library/Logs/course-brain/blackboard-poll.log
```

See what a scan would file, without writing anything (includes a rundown of the discussions it detected):

```bash
python3 scripts/blackboard-scan.py <code> --dry-run
```

Reinstall both launchd agents after editing a class (otherwise it happens at the next 07:05 run):

```bash
python3 scripts/gen-schedule.py
```

See what's scheduled:

```bash
python3 scripts/gen-schedule.py --dry-run
```

Lint the repo (run this before committing class or assignment changes):

```bash
python3 scripts/check.py
python3 scripts/test_blackboard_scan.py
```

## When it breaks

| Symptom in the log | Cause | Fix |
|---|---|---|
| `Not logged in · Please run /login` | Claude CLI session expired | run `claude` interactively, then `/login` |
| granola tool errors / "needs authentication" | Granola OAuth expired | `claude` then `/mcp` → authenticate `granola`. Check with `claude mcp list` |
| `claude run failed or timed out` with nothing else | headless run hung or crashed | look at the lines above it; force a run manually and watch |
| `already running (pid N), skipping` every time | a run is genuinely stuck | `kill N`, or `rm -rf /tmp/course-brain-sync.lock` (`/tmp/course-brain-poll.lock` for the poll log) if that pid is already gone; the next run takes over |
| poll log has no `=== run` line for over an hour | the agent was unloaded, or every run is deferring | `launchctl print gui/$(id -u)/com.course-brain.blackboard-poll`; if it's gone, `python3 scripts/gen-schedule.py`. `deferring to lecture-sync` every run means a stuck lecture lock; see the row above |
| lectures filed by the job but missing on another machine | you haven't pulled | `git pull` |
| `blackboard scan failed` in the log | usually the Blackboard session; an expired one is handled on its own (`blackboard.py` re-logs in once and retries) | look at the stderr line above it. If login itself is broken, run `CB_DEBUG=1 scripts/bb login` and read `~/.course-brain/login-fail.png` |
| `blackboard mirror failed` in the log | same session causes as the scan, or a class has no `workdir:` set | check the stderr line above it; a class without a workdir is skipped silently by design |
| a mirrored file keeps re-downloading every run | Blackboard reports a different size than it serves | harmless; the mirror records both and settles after one run |
| entries piling up in `inbox/blackboard-review.md` | the scan or the lecture flow flagged things they won't decide alone | process them — see [Phone approval flow](#phone-approval-flow-optional). They stay flagged until you delete them |
| `blackboard scan failed` repeatedly, or a `blackboard scan failing` ping | the Blackboard session or login is broken | `scripts/bb check`, then `CB_DEBUG=1 scripts/bb login` and read `~/.course-brain/login-fail.png`. `~/.course-brain/scan-failures` holds the streak; it clears itself on the next good scan |
| `op timed out after 90s` | no `OP_SERVICE_ACCOUNT_TOKEN`, so `op` fell back to the desktop app and stalled on a prompt nobody could answer | put the service-account token in `~/.course-brain/env` |
| `todoist sync failed` in the log | token missing or Todoist API down | check `TODOIST_API_TOKEN` / `~/.config/todoist/token`; tasks catch up on the next run |
| lecture missing entirely | note isn't in the class's Granola folder, or transcript still processing | move the note into the folder; the next run picks it up. Pending transcripts retry automatically |
| launchd agent gone (`launchctl print gui/$(id -u)/com.course-brain.lecture-sync` fails) | plist reload failed | `python3 scripts/gen-schedule.py` — it re-bootstraps |
| `no state, run: scripts/bb login` | no saved Blackboard session on this machine | `scripts/bb login` |
| `1password cli not found` | `op` isn't installed here | `brew install 1password-cli` |
| `login timed out at <url>` | the SSO flow hit a screen the script doesn't handle | rerun with `scripts/bb login --headed` and read `~/.course-brain/login-fail.png` |
| `op` says "account is not signed in" | no desktop-app integration and no `OP_SERVICE_ACCOUNT_TOKEN` | sign in to the 1Password app and enable the CLI integration, or export the service-account token |

## Setting up from scratch

On a fresh machine:

1. Clone your (private) copy of the repo.
2. Install the Claude Code CLI, run it once interactively, `/login`.
3. `claude mcp add --transport http --scope user granola https://mcp.granola.ai/mcp`, then `/mcp` inside the CLI to authenticate.
4. Set up the Blackboard session (above) and drop your Todoist token in `~/.config/todoist/token`.
5. `python3 scripts/gen-schedule.py` — installs the launchd agents (add `--no-poll` if you don't want the 30-min Blackboard poll).
6. Force one run (above) and read the log.
